# ととのえ｜Totonoe

日本語の表記を「ととのえる」ための Chrome 拡張機能です。第一弾として、選択した日付を自分で決めた書式に右クリックひとつで整えます。

```
6/5              →  6月5日(金)
2026-09-21 14:30 →  9月21日(月) 14:30
明後日            →  2026/9/23(水)
```

書式はユーザーが自由に定義できます。入力側の読み取りパターンも正規表現で差し替えられるので、
自分の職場でよく出てくる書き方に合わせられます。

## 使い方

1. ページ上で日付らしい文字列を選択する
2. 右クリック → **日付を整形** → 使いたい書式を選ぶ
3. 入力欄の中ならその場で置き換え、読むだけのページならクリップボードにコピー

書式の編集はツールバーのアイコン、または右クリックメニューの「書式を編集…」から。

## インストール

### Chrome ウェブストアから

（審査通過後にリンクを載せる）

### GitHub から（unpacked インストール）

「unpacked（パッケージ化されていない拡張機能）」は、zip や crx に固めずソースのフォルダをそのまま
Chrome に読み込ませる開発者向けの入れ方です。ウェブストアを経由しないので審査を待たずに使えますが、
自動更新はされません（更新するには `git pull` して再読み込み）。

1. このリポジトリを clone するか、[Releases](../../releases) の zip を落として展開する
2. Chrome で `chrome://extensions` を開く
3. 右上の **デベロッパーモード** をオンにする
4. **パッケージ化されていない拡張機能を読み込む** を押し、`manifest.json` のあるフォルダを選ぶ

コードを書き換えたら、同じ画面の再読み込みボタンで反映されます。

## 書式トークン

ラテン文字だけがトークンです。「月」「日」「(」などはそのまま書けます。

| トークン | 出力 |
|---|---|
| `yyyy` / `yy` | 2026 / 26 |
| `M` / `MM` | 9 / 09 |
| `d` / `dd` | 21 / 21 |
| `ddd` / `dddd` | 月 / 月曜日 |
| `E` | Mon |
| `H` / `HH` | 14 / 14（24時間制） |
| `h` / `hh` | 2 / 02（12時間制） |
| `m` / `mm` | 30 / 30（分） |
| `a` | 午前 / 午後 |
| `[ ]` | 中身をそのまま出力（例: `yyyy[年]` → `2026年`） |

`M` が月、`m` が分です。ここだけは衝突するので、設定画面のライブプレビューで確かめながら書いてください。

例:

| 書式 | 結果 |
|---|---|
| `M月d日(ddd)` | 9月21日(月) |
| `M月d日(ddd) H:mm` | 9月21日(月) 14:30 |
| `yyyy年M月d日(dddd)` | 2026年9月21日(月曜日) |
| `yyyy-MM-dd` | 2026-09-21 |

## 入力パターン

既定では次を読み取ります。年が省略されていれば今年として扱います。

- `2026-09-21` `2026/9/21` `2026.9.21` `2026年9月21日`
- `6/5` `9-21` `6月5日`
- `今日` `明日` `明後日` `昨日` など
- 後ろに時刻がついていれば拾う: `14:30` `14時30分` `午後2:05`

設定画面から正規表現で追加・変更できます。名前付きグループで値を渡します。

| グループ | 意味 |
|---|---|
| `y` `M` `d` | 年・月・日 |
| `H` `m` | 時・分 |
| `ampm` | `午前` / `午後` |
| `rel` | `今日` `明日` などの相対表現 |

例: `20260921` のような詰めた書き方に対応させる

```
(?<y>\d{4})(?<M>\d{2})(?<d>\d{2})
```

## 権限について

| 権限 | 用途 |
|---|---|
| `contextMenus` | 右クリックメニューを出す |
| `storage` | 書式とパターンを保存する |
| `activeTab` + `scripting` | メニューを押した瞬間のタブにだけ、置換/コピー処理を差し込む |

`host_permissions` は宣言していません。常駐する content script もなく、
メニューを選んだ瞬間にだけそのタブでコードが走ります。閲覧履歴もページの内容も、どこにも送りません。

## 開発

ビルド不要です。素の ES modules をそのまま Chrome に読ませています。

```sh
npm test          # 変換ロジックの単体テスト（node:test）
npm run build     # 配布用 zip を作る
```

```
src/
  core/date.js       ブラウザ API に依存しない純粋関数（パース + 書式）
  core/date.test.js  その単体テスト
  settings.js        chrome.storage の読み書き
  background.js      service worker（メニュー登録 + 実行）
  options/           設定画面
```

変換ロジックは `src/core/date.js` に閉じ込めてあります。Chrome の API を一切触らないので、
Node からそのまま import してテストでき、将来 CLI などに転用もできます。
